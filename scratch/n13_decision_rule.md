# N13 decision rule — rebuild every dataset with the corrected solver

- **Written:** by Claude Code on 2026-10-04 at the owner's request. Owner decision, 2026-10-04: rebuild every
  dataset with the corrected pre-outage check.
- **When it takes force:** when the N13 run (`scratch/run_prompt_n13.md`, Step 1) copies this file unchanged
  to `scratch/n13_decision_rule.md` and hashes it, after the owner has pushed it.
- **Replication, not a fresh prediction.** No rebuilt dataset and no result on one exist when this is written.
  Every verdict below was decided once already, on the old datasets (N5, N9, N10, N11, N12), and those
  outcomes are known. The paper must call these verdicts replications on corrected data.

## 0. Why

Every dataset was built by one loop: draw an operating condition, solve its pre-outage (N-0) state, keep it
only if feasible, then solve every outage. All of those solves used the pinned pandapower solver, whose
Q-limit loop switches generators PV→PQ and never back.
- **Labels:** corrected afterwards by the PV/PQ switch-back loop (N2, N5, N9, N10, N11).
- **Inputs (`vm0_*`):** never corrected. On case118, 1,400 of 1,500 base cases needed the N-0 correction;
  the minimum changed by > 1e-6 pu in 712 of them.
- **Which conditions were kept:** decided by the uncorrected N-0 solve. On case118, 9 kept base cases fall
  below 0.94 under the corrected solve. The corrected solve raises the N-0 minimum more often than it lowers
  it (457 vs 255), so some rejected draws would have been kept.

Only a rebuild fixes all three. A diagnostic arm (§3) also tests whether the input mismatch caused misses.

## 1. The rebuild (primary)

**What stays the same.** Each dataset is rebuilt with its original build script, invocation, network, RNG
shard seeds, sampler, stress setting, generator voltage floor, accepted-count target and N-0 thresholds.

**What changes: the solver.** Every power-flow solve is a pinned solve followed, when any generator's Q-limit
state contradicts its voltage, by the N2 switch-back loop:
- case118: `scripts/sts_n2_label_audit.py` `corrected_solve`;
- the other networks: the N10/N11 version, which switches only the helper sgens.

The corrected solve is used for three things:
1. **Acceptance.** A draw is accepted iff its corrected N-0 state converges, its minimum is ≥ 0.94 pu, and,
   where the original build had a thermal check, the loading of the corrected N-0 state passes it. A draw
   whose N-0 switch-back fails is rejected and counted as "N-0 correction failed".
2. **Inputs.** `vm0_<i>` is the corrected N-0 voltage at bus i; `n0_min_vm` is its minimum.
3. **Labels.** Each outage row's `min_vm`, `max_vm`, `argmin_bus` and `violation` (min_vm < 0.94) come from
   the corrected state. A row whose switch-back fails is kept with `converged = False`, so every loader drops
   it.

**The base set changes, as intended.**
- Each build replays the original draw sequence and stops at the same accepted count.
- After the first acceptance that differs, the mode alternation and RNG use differ, so the rebuilt base set
  differs from the old one.
- Report per dataset:
  - the shared prefix per shard;
  - the old bases rejected;
  - the new bases added;
  - the bases common to both builds.
- Splits are regenerated by `make_splits` on the rebuilt groups. All old-vs-rebuilt comparisons are therefore
  unpaired.

**Dataset files have exactly the original schema** (same columns, same dtypes).
- `make_splits.load_dataset` takes every numeric column as a feature, so no audit column may enter the
  dataset file: not the pinned min_vm, not the switch-back status, not the outer-iteration count.
- Audit columns go in `data/sts_n13_audit_<name>.parquet`, keyed by scenario_id, outaged_type and
  outaged_idx.

**Datasets.** Nothing stays on the old solver.

## 2. Checks (a failed check stops only that dataset; its analyses do not run)

1. **Code path.** Before rebuilding, replay each original build with its original pinned acceptance, N-0 only.
   It must reproduce every stored `n0_min_vm` exactly.
2. **Shared prefix.** Per shard, the draws before the first acceptance that differs have parameters
   identical to the old build's.
3. **Label reproduction.** For every base case common to the old and rebuilt builds (same parameters):
   - its pinned outage minima equal the old stored `min_vm` exactly;
   - its corrected outage minima equal the old switch-back labels within 1e-9 pu. The old labels are in
     `data/sts_n2_label_audit.parquet`, `sts_n5_relabel095`, `sts_n9_relabel095_seed200/300`,
     `sts_n10_relabel_illinois200`, `sts_n11_relabel_*`, `sts_n11_floor09{3,6}_relabel` and, for N2R,
     `sts_n11_n2_rows`.
4. **Acceptance.** Every rebuilt base case has a converged corrected N-0 state with minimum ≥ 0.94.
5. **Failure ceilings.** Each of these must be ≤ 0.5% (the case39 precedent):
   - failed outage switch-back rows, as a share of the dataset's outage rows;
   - draws rejected because the N-0 correction failed, as a share of draws.
6. **Independent solver.** The from-scratch complementarity solver of `scratch/label_crosscheck.py`, with
   its functions imported unchanged and the network as a parameter.
   - **Validation first, per network:** with the limit rule replaced by voltage control everywhere, it
     reproduces pandapower's enforce_q_lims=False minimum within 1e-6 pu on every compared row.
   - **Rows compared:**
     - every accepted N-0 state;
     - 200 outage rows per stratum, numpy seed 20261004. If a stratum has fewer, all are used. The strata
       are:
       - (a) label flipped (pinned vs corrected);
       - (b) not flipped, but changed by > 1e-4 pu;
       - (c) unchanged (≤ 1e-4 pu);
       - (d) corrected min_vm in [0.94, 0.945).
   - **Why the tolerance is 1e-3 pu, not tighter.** The switch-back loop accepts a generator as consistent
     within TOL_V = TOL_Q = 1e-3 (`scripts/sts_n2_label_audit.py`). The independent solver enforces the rule
     to about 1e-7. In the earlier check (`data/sts_label_crosscheck_rows.parquet`), 12 of 201 rows
     differed by > 1e-6 pu and 5 by > 1e-4 pu (max 5.0e-4). All 201 labels agreed and every independent state
     was consistent. A 1e-6 pu stop rule would fail on solver tolerance alone.
   - **Stop rule** (any one stops the dataset):
     - the independent solve fails to converge to a consistent state on more than 2% of compared rows;
     - any label disagrees on a row where both solvers' min_vm are more than 1e-3 pu from 0.94. For an N-0
       state, the label is acceptance (min ≥ 0.94);
     - more than 1% of compared rows differ by more than 1e-3 pu in min_vm. For N-0 states, the difference
       is the max over the full bus-voltage vector.
   - **Reported:**
     - per stratum, agreement with its Clopper-Pearson 95% interval;
     - the median and max |Δ|;
     - the count of rows > 1e-6 and > 1e-4;
     - **stratum (d) as its own figure.** Label agreement inside [0.94, 0.945), with its Clopper-Pearson
       95% interval, counting the near-limit rows the stop rule skips. It cannot trigger a stop, but it is
       the best available evidence where labels flip;
     - **near-limit population over the whole dataset, not only the compared rows:** the count and share
       of all converged outage rows with |corrected min_vm − 0.94| ≤ 1e-3 pu. On these rows the label is
       set within the switch-back tolerance (on the old D94: 14.12% of 278,954 rows). This count goes in
       the paper's limitations.
   - **TOL_V and TOL_Q stay 1e-3.** Tightening them would change the N2 method, and check 3 would then fail
     by design.
- **A dataset that fails a check (owner decision, 2026-10-04): excluded.** ILL, C30, C24, D93, D95a, D96,
  D95b or D95c is excluded from the rebuilt results and from cross-network claims, and the failure is
  reported. Its old results are not substituted back in.
- **If D94 fails a check:** N13 is reported as failed, and the paper uses the old results with the input and
  base-set problem stated as a limitation, as in the cutoff fallback.
  - D94 carries the headline, Tables 1-2, Figs 2-4, safety, the budget curve, the guarantee and Mondrian.
  - N2R is built on the rebuilt D94 base cases, so it is not built.
  - The other datasets' checks and results are still reported, but the paper does not mix rebuilt networks
    with an old D94.
- **If N2R alone fails a check:** the N-2 result is reported from the old N-2 build, labeled "old build,
  uncorrected solver".

**Arm F, diagnostic: the original base sets with corrected inputs only.** Runs after tier A, before tier B.
- **Data.** For each base case of the original D94, ILL, C30 and C24, the corrected N-0 state is solved (the
  check-1 replay plus the switch-back). A copy of the original dataset is written with only `vm0_*` and
  `n0_min_vm` replaced.
  - Same base cases, rows, labels and splits.
  - Output: `data/sts_n13_armF_<name>.parquet`, with the original schema.
- **Models.** Each split and family keeps its existing M2 configuration and held-out target, taken from the
  original gate results, and is refit on train (`select_features` re-run).
- **Before the corrected inputs are used,** the refit on the original inputs must reproduce the existing
  held-out missed rate per split and family exactly.
- **Purpose:** a paired before/after attribution of the input change alone, and verdict V3. Arm F numbers
  never replace paper numbers.

**Timing (both arms).** `ms_solver` stays `data/solve_time.json`, the pinned solve.
- Switch-back outer iterations per row are reported.
- The corrected solver costs at least as much as the pinned one, so speedups computed with the pinned time
  are conservative.
- No re-timing.

**FLOOR_DOSE_RESPONSE.** The N3/N11 point predictions and ranges were made for the old builds and are not
re-scored. Only the two N11 clauses are re-applied.

**V3 (arm F, histgb, held-out point).**
- **Bins:** each original D94 base case's drift is |corrected − stored N-0 minimum|. The bins are those of
  `data/sts_n0drift_check.json`: ≤ 1e-6, 1e-6 to 1e-4, 1e-4 to 1e-3, > 1e-3. They are fixed per base case.
- **Pinned-input rate:** per split, the missed rate among test true violations in the > 1e-3 bin, from
  `data/sts_n0drift_check.json` → `per_split[].missed_by_n0_drift`.
- **Corrected-input rate:** the same quantity from arm F.
- **Holds if** mean_split(pinned) − mean_split(corrected) > max(std pinned, std corrected).
- **Reported, no verdict:**
  - ridge;
  - all 4 bins for both families;
  - a second binning by the maximum per-bus |Δ vm0| over all buses, with the same edges. Many bases with
    an unchanged minimum still had other inputs move.

## 5. Descriptive (no verdict)

- **Per rebuilt dataset:**
  - draws; accepted; rejected by reason (voltage, thermal, N-0 correction failed);
  - the base-set changes from §1;
  - VR, BM, CBM and the min_vm range;
  - the over-voltage share (max_vm > 1.05 pu) and the critical-bus shares (argmin_bus), both on the
    corrected state;
  - failed rows;
  - mean and max switch-back outer iterations.
- **Old vs rebuilt, side by side,** for every number in the paper's tables. The comparison is unpaired, with
  the std rule applied.
- **Old rejected draws that pass the corrected check:** for each original build, replay its rejected draws,
  solve their corrected N-0 state, and count how many would now be accepted.
- **Arm F vs original, paired per split:** missed, escalation and speedup B, as mean ± std of the
  differences.

## 6. Commitments

- **Fixed:** no extra seeds, networks, limits, candidates, bins, strata, tolerances or smoothing values after
  hashing.
- **Reported either way:** every verdict, including any that flips against the paper's current story.
- **Replacement (owner decision, 2026-10-04).** The arm-S results on the rebuilt datasets replace the old
  results as the paper's primary numbers, whichever way they move. The old results are reported as "before
  the rebuild". This is fixed now so that which numbers lead cannot be chosen after seeing them.
- **Deviations:** logged in `notes/overnight_status.md` and `scratch/n13_result.md`. Any verdict touched by
  a deviation is marked "with deviation".
- **History unchanged:** the N3, N5, N9, N10, N11 and N12 verdicts stay reported as results on the old
  builds.
