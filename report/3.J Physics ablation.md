
In the specific ablations, I intentionally left out the aggregate loading (agg_loading), so the feature matrix does not have any direct information about line loading. Although the total demand is concealed from the model, the feature matrix contains pre-outage voltages (vm0_\*) and other physics features tested below. All results below are from tests without agg_loading.

I tested five different setups: baseline, +F1 (add pre-outage branch flows on the outaged element), +F1+F2 (add F1 and the full pre-outage loading vector), +F1+F3 (add F1 and the LODF rows), and +F1+F2+F3+F4 (add F1, F2, F3, and electrical distance F4). For each configuration, I trained ridge and histogram-based gradient boosting and conducted tests with hyperparameters re-searched per configuration and with them fixed. I report mean absolute error (MAE) to measure prediction accuracy and also include seed standard deviation to account for randomized seeds starting at different points. The best configurations (with hyperparameters re-searched) had a MAE of 0.00371 \pm 0.00010\ for ridge and 0.00153 \pm 0.00011\ for histgb. The additional features contribute no meaningful increase in performance compared to the basic ones, as it is less than the seed standard deviation.

The one negative outcome obtained here is that including F2 (the entire vector of pre-outage loadings) worsens ridge's results. When comparing the model with baseline versus with +F1+F2, the ridge MAE increases by +10.82\% (baseline \(0.003754 \pm 0.000133\) to +F1+F2 \(0.004161 \pm 0.000247\ in the re-searched runs). This decrease in performance is greater than seed variability regardless of whether the hyperparameters are adjusted or not.

To investigate further, I ran a three-arm permutation control: the basic model, the model with real F1 data, and a model with shuffled F1 data. In a quick single-seed histgb check, the MAE values were 0.0015638 for baseline, 0.0015539 for real F1, and 0.0015300 for shuffled. The shuffled arm was lower than real F1 by (2.40\times 10^{-5}), but this difference is small enough that it falls within normal, as histgb seed standard deviation is ((\approx 7.58\times 10^{-5})). In addition, I also conducted a leakage audit to ensure the data was not training the model from previous tests. The audit reproduces the four F1 columns (pre_p_mw, pre_q_mvar, pre_loading_percent, pre_i_ka) from scratch across 25 different scenarios, and everything matched up, proving there was no accidental data leakage. The input data varies across different scenarios, meaning I can conclude that any change in values from the audit was not due to constant features.

Since shuffling the F1 data did not significantly decrease performance, the data itself does not contribute meaningful real-world physical information that would boost performance beyond the existing per-element encoding in the branch one-hot representation.
