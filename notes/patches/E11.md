## 4. What must change
- **C10 (a):** not end-to-end: data generation (the labelled dataset), model training and hyperparameter search are
  excluded, as is the base-case solve that produces the pre-outage voltage features (P-029, ~0.5% amortized). Scope
  the claim to per-contingency screening cost, or point to the break-even sentence.
- **E11a (after b):** break-even — how many base-case sweeps (186 contingencies each) must be screened before the
  per-case saving pays back the one-time cost: about 4,200 sweeps counting dataset generation only, about 8,000
  including training and search, at the current operating points. Context in the same place: 10 parallel solver
  workers on the same machine already give ~5.4× over serial solving, i.e. more than the gate's ~1.6×, and the two
  can be combined.
- If the headline operating point changes (`Top5-2d-E5.md`), break-even keys exist only for ridge 0.94 / histgb 0.97;
  the per-target table `break_even.json` → `break_even_table` covers other targets (gen_only accounting) — read the
  matching row.
- (c) note (2b-6, optional): histgb t_surr re-measured at 0.00346 ms vs committed 0.00241 ms; negligible for speedup
  but the ± shown is not reproducible as-is; optional footnote.
- **P-033 (ledger, MINOR):** N6's cold minimum (7.53 ms) is below the committed `ms_solver` 9.14 ms (min over ~2–3 bases, different generator config); medians agree (9.25 vs 9.51 ms). Before printing any absolute time (l.147 "9.14 ms, which is the minimum over 400 timed solves"), the author should say "median" or give both; ratios barely move because speedup ≈ 1/escalation.
- N6 landed (`data/sts_n6_warmstart_timing.json` + manifest): starting each outage solve from the pre-outage
  solution cuts the median per-solve time by 13.7% (9.25 → 7.98 ms; median time ratio 1.16; paired median saving 1.27 ms; identical
  labels on all 2,232 pairs). A warm-started solver is the fairer baseline, and it shrinks every speedup by that
  factor. Optional one clause (author decision). Caveats if used: 12 base cases, one seed; the machine's load
  average was high during the run (≈ 49 / 87 over 5 / 15 min), and this run's cold *minimum* (7.53 ms) is below the
  committed 9.14 ms minimum — the committed t_solve is a different sample; do not mix the two bases in one ratio.
