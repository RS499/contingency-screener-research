## 4. What must change
- Replace (a) with two separate points (STS-20):
  1. **grouping:** the 186 outages of one base case share its load and generator draw, so the independent unit is
     the base case (300 per test split), not the row (~55,800); the splits are already made by base case.
  2. **marginal vs conditional:** the 90% coverage holds on average over all rows, but not per element or per base
     case. Numbers (target 0.90): per-element coverage falls as low as ~56–57%; 18% (ridge) / 24% (histgb) of the 186
     elements are below 85%, against 0.24% expected from sampling noise alone if every element had exactly 90%; 8.7%
     of test base cases are below 85%, against 1.9% expected.
- **Operator-level statistic (one sentence + number):** at the headline points, 7.7% (ridge@0.94) / 11.1%
  (histgb@0.97) of test base cases contain at least one certified violation — a full N-1 study of one base case has
  roughly a 1-in-9 chance (histgb) of a silent miss even though "0.83% of violations" sounds small. Every test base
  case in this dataset has at least one violation, so "share of base cases" and "share of base cases with a
  violation" coincide here; say which one is meant.
- Optional (only if space): the cluster-bootstrap standard error of test coverage is ~5.6–7.0× the naive row-level
  one — the effective sample size is closer to the number of base cases.
- (b) is unparseable as written (P-027 list); if kept, it must say what "lower bound" refers to.
- (c) P-010 fix sits in `E5b-E15.md`.
