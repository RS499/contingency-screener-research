## 4. What must change
**E6a — Table I row** "classical (conformal)": the repo's linearized classical screen (one base-case AC solve, one
Jacobian factorization, linear voltage sensitivities per outage) with the same one-sided conformal band. Caption:
"Four-model" becomes five (six with P-009 if it is added as a row). State in the caption that the classical row's
speedup charges its own per-contingency time.
**E6b — replace (b):** the classical linearized screen *does* give a minimum voltage (it is the new row). Its
limitation: generator (PV) bus voltages are held at their base values in the linearization, so it cannot represent a
generator hitting its reactive limit; it is accurate where the weakest bus is a generator bus and poor where it is a
load bus.
**E6c — after (d):** the classical conformal screen avoids only 8% of solves at 0.90 while missing 1.07%; conformal
ridge dominates it at all 9 targets, conformal histgb at only 1 of 9 (histgb trades missed rate for throughput).
Its MAE (3.77 × 10⁻³) equals ridge's, yet it saves 8% vs ridge's ~51% — supports "accuracy does not settle safety".
Do **not** say "the gate beats the classical screen" for both models.
**P-009 — static element ranking (same paragraph or next; also named in Discussion and conclusion):**
- Define: rank the 186 outages by how often each caused a violation in the *training* base cases; solve the top k
  for every new base case; no model of the operating point at all.
- Two budget definitions, both required, because the gate gets flagged cases "for free" (they are not solved):
  1. **Same number of solver calls as the gate escalates** (like-for-like on solver cost): at 0.90, ridge budget
     (k ≈ 91): static 96.91 ± 0.49% of violations caught vs gate 97.04 ± 0.44% (escalated or flagged) → tie; histgb
     budget (k ≈ 57): static 91.0 ± 2.0% vs gate 95.28 ± 0.98% → gate ahead.
  2. **Flagged cases also solved** (an operator must solve a flagged case to know its severity and act — the same
     argument as `E8.md`): ridge (k ≈ 138) static 99.41 ± 0.16% vs gate 97.04 ± 0.44%; histgb (k ≈ 89) static
     96.64 ± 0.50% vs 95.28 ± 0.98% → **static ranking catches more**, both beyond the std.
  - At the headline operating points the same pattern holds (see §5): at equal escalation budget the gate is ahead;
    with flags solved, static is ahead.
- Caveats to state: (i) both are scored on the same pandapower labels (P-003); if the label artifact concentrates on
  particular elements (e.g. transformer IEEE 8-5, P-020), a by-element ranking would pick it up — direction of bias
  unknown; (ii) the static ranking gives no per-case voltage and no per-case certificate; the gate does. Name what
  each provides; do not declare an overall winner.
- (e) Method baseline list must include the classical screen and the static ranking.
- NS-04 (Table I footnote †): the train-mean model predicts 0.9398 < 0.94, so it **flags every case**; that is why it
  never escalates and never misses. State that, instead of "never calls the solver".
- P-026: persistence / train-mean rows come from the committed v1 file (`data/screener_metrics.json`, model-free,
